# 视频制作的画布转换

已启用名为 workflow 的技能时，资产图、镜头划分、画幅和生成模型以该技能为准。本文件只说明节点放在哪里、如何连线、如何确认。角色参考图包含面部特写，以及正面、侧面和背面的视图；场景根据是否需要更换机位，选择四方向拼版或无人空镜。一个视频生成节点对应一段视频。视频内部可以根据剧本和用户要求包含一个或多个摄影镜头。只有明确要求一镜到底时，才禁止切镜。不得为了切换机位而强制拆分视频节点，也不得擅自删除镜头。出图以 workflow 技能里的 production.image 为准，出视频按 `production.video` 与用户已确认的节点模型。提示词按实际工作流编写。

把已确定的创作内容变成用户可以编辑、连接和继续生成的画布。创作判断由对应技能负责，本文件只说明如何落实。工具调用约定见 [画布操作手册](../SKILL.md)，不需要访问外部资料。

## 0. 逐阶段协作

使用用户实际选定的 H3 Ref2VA 或其他视频工作流，不默认改用 Seedance。制作流程：先完成本次范围的完整剧本，按当前运行模式和授权范围确认或连续推进，再根据剧本生成角色、场景、道具资产；将完整剧本划分为多个片段，为每个片段中的全部镜头编写一份视频提示词，资产直接作为视频输入。一个片段可以有多个镜头和动作，对应一个视频节点；不默认生成关键帧。用户明确提出首帧、首尾帧、构图锁定等特殊要求时，再增加对应阶段。

写资产提示词前必须读取 [资产图规范](../../workflow/references/asset-planner.md)，拆片段和写视频提示词前必须读取 [片段导演指南](../../workflow/references/video-director.md)。本文件负责画布映射，不能用操作说明代替上述具体模板。

| 阶段 | 给用户看的成果 | 满足当前模式的验收关卡后推进 |
| --- | --- | --- |
| 需求与简报 | 已知需求、尚缺的受众/时长/画幅/风格/声音/参考用途 | 故事与剧本；每轮只问当前必要的少量问题 |
| 完整剧本 | 本次范围的逐场正文、完整动作和对白/OS/VO、开头经过与结尾；梗概不能代替正文 | 根据剧本提取角色、场景和道具；不能因题目熟悉就跳过剧本 |
| 资产设计与准备 | 剧本资产清单、分类型提示词、角色面部特写及正侧背三视图等实际资产成果 | 按确认范围生成并验收素材，已有合格资产复用；通过后供视频使用 |
| 剧本分片段与视频提示词 | 每片段的剧本范围、内部镜头、预计时长、承接状态及一份完整多参提示词 | 一个明确范围的完整片段小样，不按内部镜头各建生成任务 |
| 视频小样 | 实际视频、已检查内容及需调整之处 | 用户确认效果后扩展其同意的镜头范围 |
| 批量制作与交付 | 对应片段的素材、实际规格、剩余问题 | 整集用画布上的视频剪辑节点连线、排序、裁剪并导出；没有该节点时交付片段，不宣称成片 |

- 每阶段先完成可审阅成果。普通/半自动的未确认阶段使用 `askUser` 或文字询问，目标模式在已授权目标内连续推进而不机械等待；额外付费、超范围算力及宿主权限仍须实际授权，不把每次工具调用变成一次提问。
- 用户已明确确认或授权连续完成的具体阶段直接沿用。确认简报不代表确认剧本，确认资产生成不代表验收生成结果，允许一个小样不代表允许整片批量生产。
- 普通/半自动使用 `askUser` 时 `title`、`question` 必填；多问题 `fields` 使用唯一名称，不得同时传 `fields` 与顶层 `options`。确认被跳过、取消或未回答时保留成果、暂停且不循环追问；目标模式不发起普通阶段的提问。
- 用户调整内容后，先同步更新受影响的简报、分镜和节点提示词，再展示更新后的阶段成果。比如改为“无旁白”时，不能让画布保留旧旁白，而另用聊天里的新提示词直接生成。
- 画布制作沿节点内的实际配置与生成能力执行；不能为了绕过阶段确认或节点参数缺口，转用其他生成工具偷偷换一套方案。

## 1. 读取现状，再决定需要哪些节点

用 `getCanvas` 确认目标画布概览，按需传 `include: ["nodeTypes"]` 查询可用类型。用 `findCanvasNodes` 定位已有节点；已知 ID 时直接用 `getCanvasNodes` 查询必要字段，用 `getCanvasEdges` 查询局部连接，用 `getNodeTools` 查询函数。遵守分页、截断信息和游标，不读取整图详情；全图任务分批完成，仅保留当前批次和摘要。在当前画布制作时沿用当前画布；只有明确需要新画布或切换已有作品时才使用相应工具。

- 节点类型从 `getCanvas` 的 `availableNodeTypes` 选择，内容修改与生成函数从 `getNodeTools` 返回的 `nodeTools` 清单选择，再通过 `nodeTools` 执行。名称相似不代表能力相同，不把示例名称当作固定类型 ID。
- 用剧本场号、片段号或用户已有名称定位内容；内部镜号保留在片段计划和提示词中。结合文本、素材及连接区分同名节点，续作时只补当前缺项。
- 文本、图像、视频是内容职责，不强制每个环节都建节点。已经存在的媒体输出可以直接连接下游，不另建复制结果的节点。
- 先完成当前已确认阶段的一个制作单元，填内容、核对引用，再展开获准的范围。资产未确认时不批量建立整片视频节点，也不先建一批空节点再补内容。

## 2. 内容落在可编辑的位置

| 内容 | 放在哪里 | 怎样使用 |
| --- | --- | --- |
| 创意简报、完整剧本、片段与镜头表 | 文本节点 | 保存可编辑的正文和规划；不直接连到图片或视频生成节点。 |
| 角色、场景、道具设计 | 对应资产的图片生成节点 | 按资产图规范填写：角色面部特写加完整三视图，场景/道具按各自类型与画风布局；不把片段动作、对白、运镜当成出图提示词。 |
| 已确认角色图、场景图、道具图 | 已有媒体输出或素材节点 | 直接复用并连接多参视频节点；已有文件通过实际素材导入函数装入节点。 |
| 一个片段的全部镜头 | 一个视频生成节点的提示词 | 从本段已确认的剧本与镜头计划写实际模型支持的提示词，包含真实参考、镜头顺序及必要风格约束；不把内部镜头拆成多个节点。 |
| 特殊要求的关键帧或首尾帧 | 对应图片生成节点 | 仅在该路线已明确确认时准备，不作为多参制作的固定中间步骤。 |

操作顺序为：`addNode` → 记录返回的 `node.id` → `getNodeTools` 查询函数 → `renameNodes`（需要时，传 `renames` 数组）→ `nodeTools` 填内容。创建时也可直接设置名称；已有节点从修改内容开始。只创建空节点或把提示词留在聊天里，都不算完成画布搭建。

当前内置节点可能提供 `node:setText`、`node:setImage`、`node:setVideo`、`node:setAudio`、`node:setPrompt`、`node:getConfig`、`node:setConfig` 和相应生成函数；只有本次函数清单确实包含它时才使用，参数读取该函数说明，不将这些名称套给其他插件。

文本节点写入的是可供下游读取的文本内容，不等同于触发节点内的语言模型。文字已由当前助手完成时直接写入，不需要再次生成。用 `getCanvasNodes` 的 `fields: ["data"], dataKeys: ["textPath"]` 读取正文文件位置，再读取实际文件核对；需要查看当前内存正文时用 `path: ["outputs", "text", "value"]` 分段读取。默认详情未包含正文不代表节点为空，也不要猜路径或直接改文件替代节点函数。

新节点的文件或模型可能仍在初始化。收到明确的“尚未加载”错误时保留该节点，先处理独立内容，待初始化后再尝试；不要删除重建，也不要把暂未加载和确实未配置模型混为一谈。

素材导入必须使用已存在且可读取的文件。图片名称、描述、待生成提示词都不能当作图片文件。已有媒体在画布上时直接复用；缺少导入能力则明确该缺口，不能用文本形式的文件路径代替实际媒体输出。

## 3. 连接输入依赖，不连接制作步骤

先读取两端真实端口，再用 `connectNodes` 连接输出与兼容输入。端口 ID 和类型从最新节点信息获取。每条边都应回答“下游要使用上游的什么内容”。

- 已连接的文字会作为上下文整段加入提示词，所以剧本和片段表不能当装饰线接入生成节点。助手先读完整剧本，再把本段原文和全部内部镜头转写到目标提示词中；剧本仍是内容来源。
- 图像生成用于资产准备，视频直接接入已确认资产，以多参提示词描述整个片段；风格图仅提供画风参考，角色、道具和场景用实际资产绑定，也不能把角色三视图变成视频里并排的三个角色。
- 风格图只用于已确认的配色、笔触或材质；角色图约束身份外观，场景图约束环境空间，道具图约束物件形制。视频、音频参考仅在当前任务需要且目标实际支持时加入，不机械连接全部资产。
- 接线与排序用入边第 N 项核对参考序号；在提示词里写清素材名称与具体用途，不能只连边，或写“若附带参考图”。H3 正文标记只使用官方 `<Subject N>` / `<Picture N>`（见 h3-prompt-writing 与 video-director），不要把接线核对用的 `{{ref N}}` 写进 H3 正文。多个角色分别说明谁做什么，不能让模型猜素材对应关系。
- 普通参考图不一定是视频的首帧或尾帧。首尾约束需要支持该方式的实际配置和正确顺序，不能仅在提示词里写“作为首帧”便宣称设置完成。
- 先接线，再用 `getCanvasEdges` 的 `nodeIds: [目标ID], direction: "incoming"` 分页读完整目标入边。用 `getCanvasNodes` 的 `fields: ["data"], dataKeys: ["referenceOrder"]` 读取目标排序，用 `fields: ["ports", "outputs"]` 分批读取源节点并核对引用编号，最后调用目标的 `node:setPrompt`。H3 生成正文写进 `prompt`，审阅用中文对照写进 `promptZh`。其他模型的正文语言和格式按实际能力及用户要求。默认详情不返回这些字段；分页和字段截断都须按[画布读取规则](../SKILL.md#读取画布)补齐。文字和媒体共用编号，不能把第一张图片一律写成参考 1。编号无法确认时不猜、不触发生成；接线、删除或排序改变后重新核对。
- 两个视频节点的前后排列不要求连边。只有下段实际使用上段视频作为参考、延续等输入且目标支持时才连；剪辑顺序写在名称、位置或说明中。

当前内置节点按目标输入端口（通常为 `in`）收集有效入边。存在 `data.referenceOrder[端口ID]` 时，按其中的键排序，键为 `encodeURIComponent(JSON.stringify([source, sourceHandle]))`；未列入的项按入边顺序排在后面，没有排序配置时保持入边顺序。列表中第 N 项就是 `{{ref N}}`。这些是核对依据，不是让助手直接修改节点数据的接口。

H3 提示词开头用 `<Subject N>` / `<Picture N>` 定义主体、场景、道具及稳定特征（编号与入边排序一致）；之后按本段原镜号逐镜写动作与空间、单一主运镜、完整台词和声音，最后写已确认风格与必要约束。镜头编排见 [导演指南](../../workflow/references/video-director.md)。不能用一句“引用小蝌蚪和池塘，游向青蛙”替代整段剧情与镜头，也不能仅因有标记便宣称模型已准确遵循。

生成用到的上游内容必须准备好。可先搭好依赖并填写下游提示词，但空输出、尚未生成的图像不能作为已就绪参考启动下游。

## 4. 触发生成前核对当前能力

读取生成节点实际提示词、配置和参考，展示本次对象与数量、模型、规格、时长、提示词及费用。普通/半自动按关卡确认。自动出图可在已授权的对象、数量和费用范围内生成、检查和返工。目标模式可继续已授权生成范围。单张、变体和小样均计入授权，一个具体批次可确认一次。超范围追加、重生成或可能收费的重试须重新确认。费用无可靠报价时说明未知。只要求搭建或修改提示词时，完成相应的画布修改即可。

模型、比例、分辨率、模式、时长与声音选项必须与用户当前确认一致。需要核对时，通过本节点的 `node:getConfig` 读取当前配置及可用模型能力；沿用用户已确认且满足任务的配置，不为普通编辑重新选模型。图片模型按[画布主技能](../SKILL.md)的选择规则确定。视频尚未确定主模型时，按实际生产配置和远端 ComfyUI 可用权重选择，不凭文件名猜测能力；统一 H3 Ref2VA 双采工作流必须显式选择已安装主模型，不预设加速 LoRA。提示词写“9:16”不能让 `16:9` 节点变成竖屏，写“6秒”也不能覆盖实际 `4` 秒。

需要调整时，通过实际提供的 `node:setConfig` 只修改本次所需选项，参数和支持范围以函数说明及 `node:getConfig` 为准；切换模型时一并提供供应商与模型。配置修改不触发生成，核对生效结果后再按已确认范围调用生成函数。目标确实没有可用配置能力时，才指出具体节点与待调整选项，请用户处理。不得把参数塞进 `node:setPrompt`、直接改画布 JSON，或转用媒体工具绕开冲突。

节点只为未设置或不兼容的选项补默认值：图片使用模型支持的最低分辨率，比例依图片项目设置；视频使用支持的最短时长和对应最低分辨率，画幅优先遵守用户确认的镜头合同和项目 `production_profile.aspect_ratio`，均未指定时默认 `16:9`，并以实际工作流支持的可选比例为准。声音默认开启并服从模型音频能力。已有有效设置不被默认值覆盖，也不主动把用户已确认的较高规格改成默认最低值。

按已确认依赖推进：完整剧本 → 角色/场景/道具资产 → 剧本分片段与逐段多参提示词 → 片段小样 → 获准的其余片段。规划表记录时长，H3 Ref2VA 允许按官方 [Shot N] 标记切镜，后续镜头写 At MM:SS.mmm；明确单镜到底时只写 [Shot 1]。已有资产直接复用，不逐镜增加关键帧，不对同一节点重复发起生成。

请求失败时先读取错误并检查当前参数。在已确认规格内可以纠正明确的参数格式问题；不能自行降分辨率、缩时长、换模型/模式、删除参考或改变声音来“跑通”。这些变化要先解释影响并询问用户。同类错误未找到原因时停下，不连续试不同制作路线。

## 5. 后台开始与完成分开处理

发起前记录该节点原有输出。生成函数返回“已开始”后，当前步骤仅是已提交；不要立即宣称有新素材，也不要再次调用同一生成函数来等待结果。

- 优先使用工具实际提供的完成通知、等待或状态能力。当前没有可靠状态查询时，不编造查询函数，也不把节点仍存在或旧输出仍可见当作成功。
- 可先完成其他不依赖此结果的文字和结构工作，再读取画布检查输出。需要重新生成时，旧输出不能证明本次完成；应取得新的生成结果或能够明确证明任务完成的证据，并确认媒体文件可以读取。
- 只有上游结果确实就绪且满足当前模式的验收规则，才启动下游。普通/半自动等待用户采用；目标模式按既有合同和 QC 在授权范围内自动推进。无法确认状态时保留任务待完成，不高频空转或重复提交。
- 当前媒体生成由节点持有，卸载可能取消任务。生成期间不为了整理工作而切换画布、删除或重建生成节点；整理可在同一画布移动位置。
- 本轮只换了提示词时，已有媒体仍是旧版本；报告修改完成和生成状态时分清，不能把旧图当成修改后结果。
- 生成进行中改提示词不会改变已提交的那次请求；要让修改参与下一次生成，先确认当前任务结束或通过实际停止能力取消。停止对话也不等于停止节点后台任务。

## 6. 示例：三镜头组成一个视频片段

假设已确认的完整短剧本为“林宁推门进屋，发现桌上的信，拆开信封后停住”，无对白。模型实际容量能容纳这段连续事件；节点类型、ID 与端口仍从当前工具获取。

1. 从剧本提取林宁、房间、信件，复用已有合格素材；缺项按资产图规范制作，展示角色参考板、无人物场景图和道具图并等待确认。
2. 将该连续事件作为“场01·片段01”，内部安排三个镜头：中景跟拍进屋，特写发现信件，中近景固定观察拆信后的反应。三个镜头都保留在该片段的同一份视频提示词中。
3. 只创建一个“场01·片段01·视频”节点，接入三个真实资产，核对引用顺序，按所选模型的格式写素材引用、三个镜头的动作、环境音和必要风格约束。剧本文本不直接连入节点，不额外制作开门、信件、反应三张分镜图。
4. 核对节点实际模型、模式、时长、画幅与声音，展示片段计划、完整提示词、数量与费用，用户明确批准本次算力消耗方案后再调用一次生成；展示实际片段并询问调整。其他片段仅按已获准的算力消耗范围继续，不按每个内部镜头另发一次请求。
5. 要展示结果使用 `fitCanvas`；局部排布用 `moveNodes`，只有用户要求整理整幅画布时才用 `arrangeCanvas`。多个片段不因时间先后自动连边，未剪辑时明确交付为视频片段。

## 7. 整集剪辑

多段视频合成一集时，只在当前画布使用视频剪辑节点。不要调用 ffmpeg 工具做拼接、转场或成片导出。

1. 用 `getCanvas` 的 `include: ["nodeTypes"]` 按名称「视频剪辑」找到节点类型。当前画布已有该节点就复用，不另建。
2. 把要进入本集的视频输出连到剪辑节点的视频输入。
3. `getNodeTools` 读取该节点实际函数，再按剧情顺序加入时间轴、调整顺序和入出点、设置画幅，然后导出 MP4。画布文件名为 `EP001`，或同一集的另一版 `EP001V2`、`EP001-V2`。成片名为项目名加集号，带版本时再加 `V**`，例如 `咪咪EP001.mp4`、`咪咪EP001V02.mp4`。不要改用别的集号来绕过文件名。
4. 用该节点的导出状态函数读取成片路径。抽帧和媒体探测仍可用 ffmpeg、ffprobe，这两项不代替剪辑节点。

## 8. 核对画布交付

完成后用 `getCanvasNodes` / `getCanvasEdges` 核对受影响节点、文字或提示词、局部连接与输出，按需 `fitCanvas` 展示本次范围。检查截断提示，必要时沿 `path` 分段补齐内容。不要把交付核对变成默认重排整幅画布；若已按用户要求调用 `arrangeCanvas`，它已适配视口，无需额外整理或重复适配。标题或位置不能代替内容验证。

分别报告已写入内容、已建立引用、已提交生成、已有新产物、已查看验收和已合成的部分。只有文件工具时不能用直接编写画布文件冒充实时操作；缺少画布工具时保留创作成果，并明确需要打开目标画布或启用相应能力。

## 参考依据

操作时使用本手册、已安装的本地制作指南和实际工具返回值，无需访问外部资料。

### 成片质检设置

视频节点 getConfig 返回 qcOverride、qcDefaults、qcChoices；refreshQcChoices=true 只读刷新，不启动 GPU。setConfig 中 qcOverride=null 继承系统，{mode:"off"} 关闭自动 QC，{mode:"custom",qcMethod,qcLevel,qcTrigger,videoQcModelId,audioQcModelId} 自定义。只用用户已启用的实际模型 ID；Gemma 视听选择同一完整文件标识。用户未要求时不更改。当现有提示词、格式、实际参考、时长、画幅及音轨一致时，调整权重、LoRA、采样、种子、分辨率、生成主机或质检策略可保留原提示词正文。新增费用或超出次数仍按本次方案确认。手动质检默认采用该成片记录的策略，明确重新验收可传 qcOverride，不重复调用、不得跳过验收。

### H3 高级采样（兼容二采）

getConfig.models[].h3Advanced 声明支持及原工作流默认值；getConfig({refreshComfyChoices:true}) 返回当前 ComfyUI 的模型、LoRA、samplerChoices、schedulerChoices，不开机。setConfig 可整体替换 h3Options（loraStrength、extraLoras: [{name,strength}] 最多3项按顺序加载、sampler、scheduler、videoShift、audioShift）；null 恢复高级默认。loraName="" 仅关闭主 LoRA；要关闭全部也清除 extraLoras。用户未要求不得更改。实验预设只用于用户明确选择；不自动叠加 Turbo 和加速 LoRA。仅改变高级采样参数时保留原提示词。实际参考、格式、时长、画幅或音轨变化时，核对现稿是否仍适用，只修改受影响内容。


## 成片归档与废片清理

1. 每段视频通过质检并被选为成片后，从完成任务取得实际输出路径及本次生成参数，创建所需目录后，调用 archiveAcceptedVideo 在当前工作区的成片目录独占保存副本及对应质检记录。项目未指定交付目录时使用 `成片/`。保留节点原始输出路径，复制成功并核对目标文件存在、大小与源文件一致后再交付。
2. 文件名使用 `EP{集号}_S{片段号}_{一采}plus{二采}steps_lora-{LoRA清单}.{原扩展名}`。集号至少三位、片段号至少两位，沿用剧本合同编号。同一片段包含多个摄影镜头仍保存一个文件。例：`EP001_S03_8plus4steps_lora-none.mp4`。单采工作流只写实际总步数，例如 `25steps`。无法取得实际参数时先核对生成记录，不用当前节点的新设置推测。
3. LoRA 清单按实际加载顺序记录权重文件短名（去目录和扩展名）及强度，如 `lora-filmLook@0.8+skin@0.6`；没有外挂 LoRA 写 `lora-none`。已确认融合 Turbo 的试镜在步数后加 `_fusedTurbo`。短名中的路径分隔符及文件名非法字符替换为下划线。保存时只允许新建；同名的不同成片在扩展名前追加 `_v02`、`_v03`。
4. 每段选片或返修结束后，自动清理本轮明确判废的独立试镜或导出副本，逐个按本轮记录的确切路径删除。仅清理由本轮创建、已确认未被引用且不需要保留的副本。仍待比较、用户指定保留、已经交付或引用状态不明的文件继续保留。节点原始输出可能由复制节点、其他画布或撤销记录引用，交由节点生命周期管理。不得按文件名模式、创建时间或整个目录批量删除。交付时报告实际保存路径、已清理数量及清理失败的路径。
5. 质检状态为 `awaitingAgent` 时保留待验收画面；提交结论后，服务端回收本次抽帧。质检过程文件由服务端管理，Agent 不扫描或删除共享证据目录。
