# 提示词反例、改进方法与 QC 反馈

## 反例 1：形容词代替画面
- 差：“林渊非常震惊，充满电影感，镜头炫酷推进。”
- 改进（导演规划）：“中近景固定，林渊原本查看检测屏，目光在读数上停住，手指按键动作停止，呼吸短暂停顿；屏幕冷光照在下颌。”
- 理由：镜头有可验证的表演事件，摄影机不必强制移动。

## 反例 2：特效只会爆闪
- 差：“灵石发出无比强烈的光，超级华丽的能量爆炸。”
- 改进：“石体裂隙由内向外出现三段细弱脉冲，托盘边缘同步出现局部冷色反射；光沿裂隙重新汇聚到石体中心，随后减弱。”
- 理由：可执行的起源、传播、反馈、收束，比笼统‘炫酷’更易质检。石体具体形状依批准图。

## 反例 3：运镜破坏动作
- 差：“高速打斗时镜头同时推进、旋转 360 度、升高并切到特写。”
- 改进：“中全景连续横向跟随两人的相对位置，维持拳脚接触点在画面内；攻击结束后停在同一景别。”
- 理由：一个主运动，避免让景别变化抢走交互信息。

## 反例 4：对白变木偶
- 差：“两人站着面对镜头说完台词。”
- 改进：“说话者注视受话对象，句末才短暂低头；听者先看说话者，再将注意移到桌上的物件。两人站位和谁说话以分镜为准。”
- 理由：视线与动作有目的，不因强调自然就堆无用眨眼。

## 反例 5：满屏施工清单
- 差：“0–2 秒中景、光源、运镜、音效；2–4 秒中景、光源、运镜、音效；4–5 秒中景、光源、运镜、音效。”
- 改进：“先定义中景固定机位与顶光，时间轴只写角色伸手、触碰、收回手及对应瞬间声。”
- 理由：持续条件写一次；时间段应追踪变化而不是复制标签。

## 从失败成片迭代
- 先归因：是提示词缺事实、动作时间冲突、参考绑定问题，还是视频模型执行失败？不把所有问题归咎于创作 Skill。
- QC 观察必须回链具体 prompt 句子和镜头事实：例如“人物手从右侧瞬移→缺少起点/接触/结束位置”。
- 修复时只修改相关导演描述，不改变经过批准的身份图、剧情、Picture 槽位和无关镜头。
- 若频繁失败，积累「失败描述→观测现象→修复描述→复验结果」；只有真实复验后才能把修复说成有效经验。
