# v1.1.8 分集制作流程

> **遗留备用（默认禁用）**：有用段落已迁入 `workflow`（改编原则、逐集剧本、导演规划、画布逐步确认、默认衍生范围等）。系统启动会把本技能加入 `disabledSkills`；用户可在设置里重新启用。断链的 knowledge（scriptCraft / narrativeGenres / shotCraft / visualStyles / sourceMap 等）**不要虚构读取**。新制作优先 `workflow`。

把旧版的「编剧流水线 + 制作流水线 + 视频工作台」转换为当前 MangaFlow 的画布操作。每步执行顺序是：**读已确认输入 → 完成本阶段 → 保存到指定画布 → 回读并检查 → 展示结果 → 等待用户确认**。聊天摘要不能代替画布成果，任务启动不能代替媒体成功。

本技能同时包含子流程和完成它们所需的专业知识。先读当前阶段**仓库中实际存在**的 reference，再按其中要求读取已提供的 `references/knowledge/`；不能仅按流程表填几个摘要就宣布完成。不调用旧版数据库、XML 写入或子 Agent 专用接口，不自动套用其他 workflow 的模型路由。

**本仓库当前随技能提供的 references（仅这些可链接、可要求读取）：**

- `references/adaptationStrategy.md`
- `references/baseAssets.md`
- `references/canvasOperations.md`
- `references/deriveAssets.md`
- `references/directorPlan.md`
- `references/episodeScript.md`
- `references/generateAssets.md`
- `references/knowledge/assetDesign.md`
- `references/knowledge/imagePromptCraft.md`

表中或正文若出现未列出的文件名，视为**尚未随仓库提供**：不要臆造补读全文，按已确认画布、用户指示与 `canvasOperations` 执行；缺文档时在阶段记录写明「无对应 reference，按既有确认推进」。

阶段验收以画布回读内容、数量、状态和用户确认为准。保持旧版核心产物及制作路线，画布存储、逐步确认和生成验收为迁移要求；不能把阶段名称相同或文件已创建当作产出一致，也不承诺两次 AI 生成逐字或逐帧相同。

## 先定位进度与画布

1. 确认当前项目、用户本次目标、已有输入与已确认结果。已有完整定稿剧本时，先按初始化步骤原样存入剧本总画布的正式节点，再进入基础资产或目标集制作，不倒推虚构小说、事件表或骨架；续作从首个未确认阶段继续。
2. 先读 [画布执行](references/canvasOperations.md)，核实工具、文件位置和当前节点。项目初始化按用户确认的工作区结构建索引（本仓库暂无独立 `projectSetup.md`）。沿用已确认配置，只补影响当前步骤的缺项。
3. 所有画布位于**用户选择的项目工作区**，不是技能安装目录。默认结构如下；已有项目可沿用用户确认的文件夹与名称，但仍保持一个剧本总画布、一个资产总画布、每集一个制作画布。

```text
项目工作区/
└─ 画布/
   ├─ 剧本.json
   ├─ 资产.json
   └─ 分集/
      ├─ 第001集.json
      ├─ 第002集.json
      └─ …
```

| 画布 | 唯一正式内容 |
| --- | --- |
| 剧本 | 项目配置、来源索引、章节事件、故事骨架与分集大纲、改编策略、各集正式剧本、画布路径索引 |
| 资产 | 全剧基础与衍生资产、父子关系、视觉设定、提示词、已选图片、使用集数 |
| 第 N 集 | 本集剧本来源/工作快照、导演规划、分镜表、参考素材节点、分镜图、视频、选用与交付记录 |

分集画布里的图片是同一资产文件的本地引用，不是另一套正式资产库。跨画布不能直接连边；先切换读取真实资产输出，再在本集建立引用节点。素材文件保留宿主返回的位置，不能为了整理画布文件夹而搬动 `assets/` 中的生成结果。

当前 `addCanvas` 没有目录参数。必须按 [画布归档办法](references/canvasOperations.md#画布创建与归档) 完成文件树归位、重新发现真实路径/ID后再填入成果，不能把所有画布留在根目录便宣布归档完成。

## 主流程与确认关口

每行是独立阶段。有链接的步骤执行前读取该 reference；无链接的步骤按本节说明与已确认输入推进，并在阶段记录注明无独立 reference。「跳过」必须有适用理由和**用户明确选择**；**跳过 ≠ 通过**，不能把取消提问、超时、沉默或「先跳过」当成已确认通过。项目不涉及原著改编时，章节事件、骨架或策略可按已有输入缩短或跳过，不能凭空补造经历。

| 步骤 | 子流程 | 成果落点与本次需要确认的结果 |
| --- | --- | --- |
| 0 | 项目初始化 | 剧本画布：项目配置、范围、文件夹与画布索引（无独立 reference，按工作区结构与用户确认） |
| 1 | 来源与章节事件 | 剧本画布：实际章节与事件表；确认来源覆盖与事实（无独立 reference） |
| 2 | 故事骨架 | 剧本画布：故事核、人物弧、分集大纲、删减记录；确认分集方案（无独立 reference） |
| 3 | [改编策略](references/adaptationStrategy.md) | 剧本画布：改编原则与边界；确认取舍 |
| 4 | [逐集剧本](references/episodeScript.md) | 剧本画布：本集完整剧本；默认一集一确认，再决定续写哪集 |
| 5 | [基础资产提取](references/baseAssets.md) | 资产画布：角色/场景/道具及出场集；确认复用、新建与视觉设定 |
| 6 | [资产图片制作](references/generateAssets.md) | 资产画布：基础资产提示词与图片；先确认生成方案，再确认采用图片 |
| 7 | [导演规划](references/directorPlan.md) | 当前集画布：分场、台词统计、情绪、过渡与注意事项 |
| 8 | [衍生资产分析](references/deriveAssets.md) | 资产画布：本集衍生清单与父资产；确认全部、部分、调整或跳过 |
| 9 | [资产图片制作](references/generateAssets.md) | 资产画布：已选衍生图片；无衍生需求时明确记录跳过 |
| 10 | 分镜表 | 当前集画布：场→片段→镜头、真实资产映射及检查结果（无独立 reference；按导演规划与已确认资产落表） |
| 11 | 分镜面板落点 | 当前集画布：按实际模式建立文本、参考、图像/视频节点；确认数量、时长与连线（无独立 reference；画布操作见 [canvasOperations](references/canvasOperations.md)） |
| 12 | 分镜图片 | 当前集画布：首帧模式的分镜图；纯文本多参模式可跳过，须记录原因（提示词方法见 [图像提示词](references/knowledge/imagePromptCraft.md)） |
| 13 | 视频与交付 | 当前集画布：视频提示词/配置 → 生成结果 → 选用与交付，三个独立确认关口（见下「成片与工作流现状」） |

第 7–13 步每集循环。完成本集后让用户选择继续哪集；不要把“一集完成”理解为全剧已完成。基础资产可按已确认的剧本分批补齐，跨集仍在同一资产画布维护。

### 成片与工作流现状（已核实）

- 成片提交可选用生产目录中的视频工作流，其中包括 **`video/h3_erca_16x9` / `video/h3_erca_9x16`（二采 MiniMax H3）** 等已登记项；具体以当前 `catalog` 与用户确认为准。
- Comfy 侧 `h3_erca` **同一张工作流**内可先出一采支路视频、再继续二采放大并出最终片（同一次 Queue 内两条合成路径）；**不是**已上线的「存 latent → 人工确认 → 再二采」两阶段产品流程，勿按未实现能力承诺。
- Mangaflow 提交端目前仍按**单输出**收取成片（`outputs[0]`），即使 Comfy 磁盘上可能已有一采与二采两个 mp4，产品层也不保证同时回传或中途先推一采。向用户说明结果时以宿主实际返回的文件为准。
- 视频提示词编写与审核若走通用制作技能，可参考 `packages/skills/workflow` 下视频相关文档；本 v118 包内**无**独立 `videoProduction.md` / `videoPromptCraft.md`，不要虚构读取。

## 知识如何随流程使用

| 工作内容 | 必须读取的知识 | 必须落实的成果 |
| --- | --- | --- |
| 故事骨架、改编、逐集剧本 | 有 reference 时读 [改编策略](references/adaptationStrategy.md)、[逐集剧本](references/episodeScript.md)；编剧/叙事类型等独立 knowledge **未随本仓库提供**时，按已确认大纲与用户边界写剧本，勿编造缺失文档内容 | 剧本画布：人物欲望与阻碍、人物弧、情绪推进、信息释放、反转/伏笔及具体改编取舍 |
| 基础/衍生资产设计与提示词 | [资产设计](references/knowledge/assetDesign.md)；美术风格独立文档未提供时，沿用项目已确认视觉约定 | 资产画布：角色识别锚点、场景空间与色光、道具结构、变体差异、可执行提示词和采用版本 |
| 导演规划与分镜 | [导演规划](references/directorPlan.md)；镜头设计独立文档未提供时，按导演规划字段与用户确认落镜 | 本集画布：镜头意图、信息可见范围、站位视轴、节奏和连续性 |
| 分镜图提示词与验收 | [图像提示词](references/knowledge/imagePromptCraft.md) | 本集画布：首帧状态、景别/朝向、实际参考映射、适配模型的提示词与检查结果 |
| 视频提示词与验收 | 本包无视频 knowledge 文件；按用户确认的模式/工作流与「成片与工作流现状」执行，必要时对照 `skills/workflow` 视频文档 | 本集画布：时序/动作/声音、真实参考绑定、生成结果与选用记录 |

叙事类型与美术风格由用户确认写入项目配置；未选择时提出有理由的方案，确认后再用。知识不是额外的剧情授权：定稿后不得擅自改结局、换事件顺序或加戏；风格示例不能覆盖已确认角色身份与参考图。

每次只把**本项目实际采用的方法及结果**写入对应画布。不要把整本知识文档复制成节点，也不要仅记录“已参考某技能”而没有可审阅的制作决策。

## 每一步如何确认

- 先把本阶段完整可审阅结果写入画布，通过工具回读确认已保存；文本较长可按章节、集、场拆节点，不截断正式内容。用 `fitCanvas` 展示本次结果。
- 在当前画布的「阶段记录」文本节点写明阶段/集号、输入版本、产出节点 ID、检查结果、状态与待决策项。状态区分 `草稿`、`待确认`、`已确认`、`生成中`、`失败`、`待复核`、`已跳过`。
- 展示画布名称及相对路径、成果摘要、具体问题、下一步内容。用可用的 `askUser` 让用户选择“确认进入下一步 / 修改指定项 / 重做当前步”；没有提问工具时在对话中提问并等待。用户回复之前结束本阶段，不提前创建下阶段制作节点或触发媒体生成。
- 用户答复后记录其决定。只修改用户指定项，回读修订结果再确认；**不要把检查通过、提问取消、跳过问答、超时或沉默视为批准**。「跳过」写入 `已跳过` 并说明理由，不等于该阶段产出已通过。「继续」只推进当前待确认的下一阶段。
- 用户已经明确确认的配置、资产或具体生成批次继续有效，不重复索取同一授权。若用户明确授权多集同阶段批次，可以按该范围执行并集中展示；没有这种授权时仍逐集确认，不把整项目目标当作全流程放行。
- 生成方案应包含实际模型/模式、对象与数量、提示词、参考、时长/画幅/分辨率及已知费用；未知费用标明未知。仅在当前批次范围得到确认后调用生成。失败后先核对真实状态，额外候选、改模型或收费重试不得超出已确认范围。

## 续作、修改与失败

每次续作以画布内容及用户确认记录为准，不只依赖聊天记忆。已有结果缺少确认时，先展示已有结果补确认，不重新生成。

改动上游后标出实际受影响的下游：剧本变化检查本集导演/分镜/视频，资产版本变化检查引用该资产的分镜/视频。将它们标为待复核，保留原成果与选用记录，不自动全剧重做。未受影响的确认继续有效。

来源缺失、目录未归位、工具缺失或写入失败时，说明具体未完成项和恢复步骤。不得将聊天文本、空节点、假文件路径、旧输出或任务已启动包装成阶段完成。只处理用户本次要求的范围；仅咨询或编辑技能时不创建制作项目。
