# 改编策略

将已确认的故事框架整理成编剧可以直接遵循的取舍原则。**人物数量、主要场景数量、爽点间隔等限制，以 `production_profile` 中的单集时长、改编尺度、世界规则和用户约定为准。**

## 输入

- 已确认的项目配置、章节/事件、故事骨架或分集意图
- 用户对忠实度、可改范围、风格、角色、结局与目标观众的要求
- 已有改编决策与确认记录；保留仍然有效的部分

## 原则（质量门用原则，不用死数字）

1. **角色数量与辨识度**：主角和常驻配角的数量，应以观众能够辨认、原画和成片能够稳定复用为准。功能重复的配角优先合并；无名路人不进资产表。具体档位与上限读 `production_profile` 。
2. **场景数量与一致性**：每增加一个独立的主要场景，就需要额外维护它在不同镜头中的一致性。不要无节制地增加场景。主要场景的规模根据 profile 和各集的创作意图调整。
3. **回报节奏（题材适用时）**：对抗/爽文等需要持续钩子的题材，开场与收束附近不宜长时间没有观众回报（冲突推进、钩子、关系翻转）。平静日常、关系戏或用户明确要求留白时，不因本条硬插打脸或爽点；间隔与分布跟题材和 profile 走。
4. **钩子与高潮分布**：根据戏剧回报的分布安排集数，不机械地将原著每章改成一集。对于需要持续提供戏剧回报的题材，可以将缺少回报的长段落并入相邻集或删除；一章有多个重要情节高潮时可以拆分。精彩情节可以提前，但必须记录这项改编决定，不得擅自改变原有安排。
5. **因果衔接与必须保留的承诺**：核心立场、主线选择、结局含义与必要世界规则保持。叙述顺序、配角、信息出现方式可换载体，须记下替代关系。删支线前自问：是否唯一因果来源、是否主角行动手段的唯一来源、是否知情差的唯一来源——是则不可静默删除。
6. **明确人物、场景与信息的作用**：人物、场景、信息各写清承担什么戏剧功能。合并场景时，必须确保时间和地点能够自然衔接，原本的事件或冲突可以在同一场戏中发生，信息的呈现不改变原有因果顺序。
7. **回报方式**：若题材需要，把观众在等的那一件事写进原则（身份揭开、关系翻转等；打脸仅当原文或确认取舍已有）。具体情节仍以原文和已确认取舍为准。微创新只改人设的一个反差或加一个高概念，并登记为改编决策。只采用 [genreCraft.md](genreCraft.md) 中与当前题材相符的一条创作要求，不把指令原文、示例角色和示例情节写进合同。场次与钩子见 [shortDramaCraft.md](shortDramaCraft.md)。

## 执行要点

- 提炼少量核心改编原则，每条写优先级、正面执行方式、不能越过的边界。
- 原著叙述、心理和背景落到可见动作和现场情境。需要对白、独白或旁白时，给观众理解前因、反应和代价所需的信息留够篇幅。
- 用户要求忠实时只做已允许的载体转换；新设定、角色合并、结局改动单独列为待确认事项。
- 画面与对白安排符合已确认画幅和单集时长（`production_profile`）。

## 写入画布

更新剧本画布上的「改编策略」类文本节点：核心原则表、删减/合并决策、世界观何时由谁引出、待确认与已确认分开标注。如果修改与已确认的故事框架发生冲突，先指出冲突，不得擅自覆盖。

核心原则模板：`优先级 | 原则 | 具体执行方式 | 负面边界`。  
取舍模板：`来源 → 保留/压缩/合并/删除 → 理由 → 对主线与人物弧的影响 → 对应集`。

## 阻塞条件

缺用户忠实度边界、缺骨架或关键事实、拟删内容与不可改承诺冲突且用户未确认时，返回公共 blocked，不输出不完整的改编策略。

## 交接要求

用户确认后：需要完整场次正文时进入 [episodeScript.md](episodeScript.md)；直接做镜头合同时进入 [story-planner.md](story-planner.md)。本文件是现行制作主线的改编入口。
