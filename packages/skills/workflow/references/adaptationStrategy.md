# 改编策略

把已确认的故事骨架转成编剧可直接遵循的取舍原则。人数、主场景数量、爽点间隔等**密度上限跟 `production_profile`（集长、改编尺度、世界规则）与用户约定走**，不把外部短剧产品的死数字当本项目门槛。

## 输入

- 已确认的项目配置、章节/事件、故事骨架或分集意图
- 用户对忠实度、可改范围、风格、角色、结局与目标观众的要求
- 已有改编决策与确认记录；保留仍然有效的部分

## 原则（质量门用原则，不用死数字）

1. **脸可维护**：主角与常驻配角数量以观众能辨认、原画与成片能稳定复用为准。功能重复的配角优先合并；无名路人不进资产表。具体档位与上限读 `production_profile` / 用户约定，不写死人数。
2. **景受一致性成本约束**：每多一个独立主场景就多一份跨镜一致性维护。只出现一次的景优先砍掉，或复用已有环境的变体（换时段、天气、前景）；不为「换景便宜」无限开新景。主场景规模随 profile 与集数意图调整。
3. **无长真空回报**：开场与收束附近不能长时间没有观众回报（冲突推进、钩子、爽点或关系翻转）。回报点的间隔与分布跟题材和 profile 走，不抄「每隔 N 集必须有爆点」之类外部公式。
4. **钩子与高潮分布**：集数跟着戏剧回报分布走，不按原著章节 1:1 切。没有回报的长段并进相邻集或删掉；一章多爆点可拆；高光可提前，但须登记为改编决策，不能悄悄改地图。
5. **因果桥与不可改承诺**：核心立场、主线选择、结局含义与必要世界规则保持。叙述顺序、配角、信息出现方式可换载体，须记下替代关系。删支线前自问：是否唯一因果来源、是否主角行动手段的唯一来源、是否知情差的唯一来源——是则不可静默删除。
6. **功能账本**：人物、场景、信息各写清承担什么戏剧功能。合并场景须同时保住时间/地点可连续、议程可同场碰撞、信息不改因果顺序。

## 执行要点

- 提炼少量核心改编原则，每条写优先级、正面执行方式、不能越过的边界。
- 原著叙述、心理与背景转成可见动作、情境、必要对白或极简 OS/VO；不为省事删掉兑现功能所需的反应与代价。
- 用户要求忠实时只做已允许的载体转换；新设定、角色合并、结局改动单独列为待确认事项。
- 画面与对白安排符合已确认画幅和单集时长（`production_profile`），不默认某种竖屏或固定短剧公式。

## 写入画布

更新剧本画布上的「改编策略」类文本节点：核心原则表、删减/合并决策、世界观何时由谁引出、待确认与已确认分开标注。修改若冲击已确认骨架，先标冲突，不悄悄覆盖。

核心原则模板：`优先级 | 原则 | 具体执行方式 | 负面边界`。  
取舍模板：`来源 → 保留/压缩/合并/删除 → 理由 → 对主线与人物弧的影响 → 对应集`。

## 阻塞条件

缺用户忠实度边界、缺骨架或关键事实、拟删内容与不可改承诺冲突且用户未确认时，返回公共 blocked，不输出半套策略。

## 交接要求

用户确认后再进入 [story-planner.md](story-planner.md)。本文件是 `workflow` 线的改编入口；不替代、不禁用 `v118workflow`。
