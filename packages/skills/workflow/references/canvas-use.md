# 画布落点

制作判断以本技能的专职参考为准。这里只规定合同写到 MangaFlow 画布的哪一类节点。操作工具以名为 canvas 的技能为准：用 `getCanvas`、`findCanvasNodes`、`getCanvasNodes`、`getCanvasEdges`、`getNodeTools`，再调用返回的 `nodeTools`。不直接改画布 JSON。

## 三张画布

| 画布 | 放什么 |
| --- | --- |
| 剧本 | 逐集正文：场号、人物、动作、对白。换机位就另起一个镜头 |
| 资产 | 角色、场景、道具的规划、原画提示词、审核结论、已选图片 |
| 分集 | 本集导演注意事项、每个镜头的成片提示词、视频节点 |

已有同名画布就接着写，不另建一套。节点内容用 `node:setText` 或 `node:setPrompt`，函数名以 `getNodeTools` 返回的为准。

## 什么连到生成节点

- 已批准的角色图、场景图、道具图连到视频节点，并在提示词里写明各自用途。
- 剧本和分镜表留在文本节点，不把整段剧本连进生图或生视频节点。
- 空的、还没生成的图片不能当作已经就绪的参考。

## 确认

每个阶段先把可查看的结果放上画布，再等用户确认。确认剧本不等于允许出图，确认提示词不等于允许消耗算力。用户没回答，就停在当前阶段。

## 画布结构（建议）

新项目在用户确认后尽量归位为：剧本总画布、资产总画布、按集的分集画布。已有正确归位则复用，不另建一套。创建画布用宿主工具；需要挪到子目录时按画布菜单「移动到」等宿主能力操作，禁止用 shell / 直接改 JSON 绕过画布宿主。

## 逐步确认关卡

每个阶段执行顺序：**读取本阶段参考 → 完成本阶段 → 写入画布 → 回读核实 → 展示结果 → 等待用户明确确认**。

- 确认剧本 ≠ 允许出图；确认提示词 ≠ 允许消耗算力；确认资产清单 ≠ 图片验收通过。
- 用户没回答、沉默、或仅看到完成通知，都**不能**当作确认，停在当前阶段。
- 用户只确认部分时，仅标记该部分通过，未确认项不得进入生成。
- 未核实归位或写入失败时，保持该阶段未完成，不创建临时正式内容冒充归档成功。
- 没有实际成片文件时，不能声称已完成全片。
