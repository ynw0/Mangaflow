# 画布落点

制作判断以本技能的专职参考为准。这里只规定合同写到 MangaFlow 画布的哪一类节点。操作工具以名为 canvas 的技能为准：用 `getCanvas`、`findCanvasNodes`、`getCanvasNodes`、`getCanvasEdges`、`getNodeTools`，再调用返回的 `nodeTools`。不直接改画布 JSON。

## 三张画布

| 画布 | 放什么 |
| --- | --- |
| 剧本 | 逐集正文：场号、人物、动作、对白。换机位就另起一个镜头 |
| 资产 | 角色、场景、道具的规划、原画提示词、审核结论、已选图片 |
| 分集 | 本集导演注意事项、每个镜头的成片提示词、视频节点 |

已有同名画布就接着写，不另建一套。节点内容用 `node:setText` 或 `node:setPrompt`，函数名以 `getNodeTools` 返回的为准。写入或修改成片提示词时，视频节点的 `setPrompt` 同时接收两项。合同中的英文 `prompt` 写入节点 `prompt`，供视频模型生成。合同中的 `prompt_zh` 写入节点 `promptZh`，供人审阅。改稿时同步更新两份内容，保持事实一致。

## 图片/视频生产的画布执行路径（默认）

生产指令（“做图”“出图”“出视频”“继续制作”“生成原画”“生成分镜”）**默认必须在画布中完成**，不能把 `generateImage` / `generateVideo` 的聊天结果当成已完成节点操作。只有用户明确要求**直接在对话里生成**媒体，才允许使用直接生成工具。普通问答、只审查、只改提示词时不触发生成。

1. **定位：** 先 `getCanvas`，再用 `findCanvasNodes` 查现有对象、镜头、生成节点和已采用媒体。继续制作必须复用相关节点；需要新节点时用 `getCanvas({ include: ["nodeTypes"] })` 查询可用类型，按实际返回 `addNode`，不得猜类型与节点 ID。
2. **填入：** 图片使用图片生成节点，视频使用视频生成节点；调用 `getNodeTools` 查询实际节点函数及参数 Schema，用 `nodeTools` 的 `node:setPrompt` 填写本次真实执行提示词，用 `node:getConfig` / `node:setConfig` 查询并配置模型及规格。不要只写纯文本方案就声称图片已准备好。
3. **连接：** 真实采用的图片素材通过 `getCanvasNodes({ fields: ["ports", "outputs"] })` 与 `getCanvasEdges` 核对输出、目标输入、已有边，按实际端口调用 `connectNodes`；不允许猜测端口、不连接尚未就绪的图片。无参考素材时不为了满足流程添加虚假连接。
4. **授权后生成：** 先展示可审核的提示词、参考、数量、模型和规格；在已有明确算力授权范围内调用图片节点的 `node:generateImage`，或视频节点实际提供的生成函数。生成只通过该节点的 `nodeTools` 完成，任务返回之前保持真实执行状态；遇到超时、未知结果先查询原节点或原任务，不重复提交。
5. **核验呈现：** 通过 `getCanvasNodes` 回读当前生成节点 `outputs` / `data`，核对结果已在画布，按需 `fitCanvas({ nodeIds: [...] })` 定位本轮成果；如节点返回失败，说明失败而不是只发 Markdown 图片表示成功。生成结果保留在原节点，下轮制作继续引用。用户明确采用后，需要固定为素材节点时用 `node:setImage` 挂载已存在工作区图片，不为归档而重复生图。
6. **中途引导：** 用户补充要求在当前工具完成后的安全轮次执行，只调整尚未开始的步骤；已经提交的生成任务不能因为普通补充消息被取消或重复提交。

当画布工具不可用、画布关闭或所需节点函数不存在时，说明具体阻塞并请求打开工作区画布；不要绕过界面直接修改画布 JSON，也不要静默退回对话 `generateImage` / `generateVideo`。

## 什么连到生成节点

- 已批准的角色图、场景图、道具图连到视频节点，并在提示词里写明各自用途。
- 剧本和分镜表留在文本节点，不把整段剧本连进生图或生视频节点。
- 空的、还没生成的图片不能当作已经就绪的参考。

## 确认

每个阶段先把可查看的结果放上画布，再等用户确认。确认剧本不等于允许出图，确认提示词不等于允许消耗算力。用户没回答，就停在当前阶段。

## 画布结构（建议）

新项目在用户确认后尽量归位为：剧本总画布、资产总画布、按集的分集画布。已有正确归位则复用，不另建一套。创建画布用宿主工具；需要挪到子目录时按画布菜单「移动到」等宿主能力操作，禁止用 shell / 直接改 JSON 绕过画布宿主。

## 逐步确认关卡

每个阶段执行顺序：**读取本阶段参考 → 完成本阶段 → 写入画布 → 回读核实 → 展示结果 → 等待用户明确确认**。

- 确认剧本 ≠ 允许出图；确认提示词 ≠ 允许消耗算力；确认资产清单 ≠ 图片验收通过。
- 用户没回答、沉默、或仅看到完成通知，都**不能**当作确认，停在当前阶段。
- 用户只确认部分时，仅标记该部分通过，未确认项不得进入生成。
- 未核实归位或写入失败时，保持该阶段未完成，不创建临时正式内容冒充归档成功。
- 没有实际成片文件时，不能声称已完成全片。
