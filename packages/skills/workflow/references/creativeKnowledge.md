# 创作知识库：选材、组合与质量约束

剧本、分镜、原画和视频导演共用 `searchVideoPromptTemplates` 查询创作参考。按当前问题选择适用条目，再用本场已确认的人物、事件、动作和素材写正文。

## 分类与职责

| library | 内容 | 适用阶段 | 不替代 |
| --- | --- | --- | --- |
| `narrative` | 22 套开篇、冲突、揭示、抉择、回报、余波等**剧情节拍** | 剧本、分场和镜头合同 | 具体连续镜头调度 |
| `memes` | 49 条有 2026 年传播记录的网络热梗与二创（含“我超威”） | 有喜剧空间的剧本对白改写 | 直接照搬库内 phrase 的原句，或使用未经授权的音轨 |
| `absurd` | 20 套反差喜剧单镜构思 | 喜剧镜头设计 | 角色身份、空间和机械结构 |
| `expressions` | 38 条表情和颜艺：常规、搞怪、极夸张、抽象 | 人物表现与原画 | 必须保持一致的角色身份特征及肖像参考 |
| `styles` | 32 种主画风与 16 种滤镜观感 | 项目风格设定、图像/视频外观 | 模型能力、实际 LUT/后期处理 |
| 原有导演模板 | 剧情用途、镜头、动作、运镜、光影、声音与可验证运动 | 视频导演 | 已批准分镜合同及 H3 正式提示词 |

这些属于**不同层级**：叙事结构管“为什么做/情节如何变化”，导演模板管“在这个镜头怎么拍”，表情管“人怎么演”，主画风管“画面是什么美术语言”，滤镜管“在原画风上如何处理颜色与光学观感”，热梗和搞怪只在有创作理由时介入。

## 检索

- 按标签检索时，每次只用一个来自工具目录的标签。先选最直接描述当前问题的标签，需要查另一个标签时另开一次检索。
- 用 `listTags` 查看拍法标签。`search.tags` 只填一个维度，数组里填一个标签。可同时提供实际时长、参考数量和画面条件。评分相同时按编号排序，使用前核对 `useWhen` 中的适用条件。
- 用 `listCreativeTags` 查看创作分类，按实际需要选择 `library`。`searchCreative` 按标签查找时只填一个 `creativeTags`，按标题或名称查找时用 `query`。
- 组合条目需要核对时，用 `checkCreativeSelection` 检查已选 ID，按实际媒介、基调和时长填写参数；只有明确提供 `storyDomains` 时才检查所选模板的适用题材是否相符，不从正文自动推断。

## 与 draftVideoPrompt 的直接衔接

检索工具的 `searchCreative` 返回带稳定 `id` 的条目。内置 Agent 在 `draftVideoPrompt.creativeSelection` 传模板 ID，外部 Agent 在 `videoPrompt` 的 `prepare` 中传 `input.creativeSelection`。镜头基调按已确认合同填写 `tone`。两条路径使用同一份制作摘要。叙事和喜剧条目的具体事件在构思分镜时使用，热梗原话如需入片也在定稿阶段确认。编写成片提示词时，事件、切点和原话均以已确认的分镜为准。

内置导演的拍法候选来自 `draftVideoPrompt.templateTags`。有具体拍摄问题时传一个标签，已有拍法时可省略。仅传 `intent` 会选择适用的导演资料。外部 Agent 需要拍法时使用 `searchVideoPromptTemplates` 的 `search`。

- 从确认的分镜填写顶层 `shotId`、`story`、`purpose`、`style`、`intent`、连续性及必需和禁止项。`lockedDialogue` 按正式剧本填本镜需要模型发出的原话。`references` 按实际槽位顺序填写文件、类型、用途和描述。
- 新镜头填写 `duration` 和 `ratio`。已有节点先用 `node:getConfig` 核对配置，仅在需要时用 `node:setConfig` 更新，随后读取 `node:getPromptContext`。画布与节点 ID 填入 `node`，确认允许写回时填 `node.write: true`。

- 已有节点时省略顶层 `canvasId`、`modelId`、`duration`、`ratio`、`sampling`、`seed` 和 `seedMode`。
- 首次 `draftVideoPrompt` 调用未通过入参校验时，按报错修正当前调用。缺 `shotId` 时补原合同编号，多传顶层 `canvasId` 时移除它并保留 `node.canvasId`。此阶段没有该次调用生成的待审稿。
- 返回 `reviewFailed` 且包含 `draftId` 时，按 `nextAction` 调用 `resumeVideoPrompt` 重审原稿。返回 `rejected` 且包含 `draftId` 时，按 `nextAction` 使用原合同和整改意见针对已经指出的问题修改。剧本或分镜版本改变后用更新后的合同重新提交。中断后遗失编号，可在原会话用 `resumeVideoPrompt({shotId})` 查询，同一镜头有多份稿时选对应的 `draftId`。仅需要重新编写整份提示词时传 `regenerate: true`；独立审核按需传 `review: true`。局部修改和对照试验直接复制、修改原稿中的指定内容，不重新编写其他部分。仅修改生成参数时复用现有提示词。
- 外部 MCP 调用 `videoPrompt`。将上述合同放进 `args.input`，并在 `args.action` 传 `prepare`。随后可用返回的 `preparationId` 和当前导演稿执行 `inspect`。需要生成请求时可将同一份稿提交 `submit`；只有实际完成审核时才提供 `review`。无需审核时也可直接在视频节点写入提示词，不要求审核号。审核结构、写回与交接见[视频审核规则](video-prompt-review.md#提交与交接)。

**宿主兼容要求**：`mustHave`、`mustNotHave`、`references` 必须是 JSON 数组，`templateTags`、`sampling`、`creativeSelection` 为 JSON 对象，`duration` 为数字；不得发送成 `"[]"`、`"{}"` 或 `"10"`。工具现在对外暴露单一对象 Schema，分支互斥由服务器在解析时验证。参数校验失败属于工具调用失败，**不意味着视频已生成，也不应自动重试消耗算力**。

创作检索可用 `library: "all"` 跨分类查询，`limit` 最多 10 条。标题与别名优先匹配。同义词归入同一条目。未命中时可收窄关键词，或沿用分镜的原有拍法。

## 一次镜头怎样选模板

1. **确认不可更改事实**：剧情目的、必须出现的动作与对白、人物身份、已批准参考图/工作流、镜头时长、机位和已建立空间关系。没有事实的部分标待确认，不让模板自行补故事。
2. **剧情节拍**：如剧本在前期，则查 `narrative`；`scope:"scene"` 是多镜头场次框架：在用户允许剪辑且片段时长足够时，可拆为同一个 H3 视频片段内的多个 `[Shot N]`，并逐镜规划切点；不得直接照搬模板中的完整场次，也不得擅自删减剧情。用户明确要求单镜时仍只能规划一个连续摄影镜头；`scope:"shot"` 是单个镜头的素材，不代表一个视频节点只能一个镜头。
3. **导演结构**：先在已有 `search` 里选满足时长、参考模式、主体数、空间锚点的导演模板。只使用对这条镜头有价值的动作和构图；已有导演方案足够好就不额外检索。
4. **表演与画风**：表情条目提供可选的脸部细节和强度。取用前先判断人物此刻在做什么、因何反应。夸张或机械化的表演适用于剧本确有喜剧、卡通或机械动作的地方。画风和滤镜只提供视觉参考，景别、机位和剪辑由已确认的分镜决定。保留人物五官、衣着和道具结构。
5. **喜剧节拍**：剧情有喜剧空间时，可适当把热梗或抽象创意写入剧本。借语气、空耳结构、反差或动作机制，**改写成该人物当场会说的话**；先让观众看到引出笑点的事件，再让人物开口。不要把 `phrase` 的原句生硬地套在不同人物身上。如果严肃镜头不适合幽默表达，不要为了加入热梗而打断剧情的发展。
6. **组合检查**：在决定组合后调用 `checkCreativeSelection`。返回 `invalid` 时不得用错误 ID；返回 `review` 时先处理时长/题材/画风冲突；`ok` 也不等于镜头质量通过。
7. **提示词编写与审核**：把所选模板各抽出**最少必要的可见事实**，参考现有 `cinematicPromptCraft` 和 `h3-prompt-writing` 编写生成文本；独立提示词审核按需使用。画布使用已有节点 `nodeTools` 设置提示词、参考与执行；不修改画布 JSON，不绕过画布直接生成媒体。

模板取用后，按 [成片审核](video-prompt-review.md) 核对本镜实际的声画、时长和参考。涉及故障或修复时沿用分镜已交代的部件、动作和结果，拍法模板只帮助观众看清这些事实。

## 热梗资料边界

- 快照截至 **2026-11-11**。数据来自有日期的媒体盘点或公开词条，包括 [数英 2026-08-21 热词专题](https://www.digitaling.com/articles/1561293.html) 和 [我超威词条](https://www.geng8.com/word/wochaowei.html)。来源字段随每条记录保存。来源与词义需要人工审校；榜单访问数不是全网热度。
- **适当写入剧本**：有喜剧空间时检索热梗，借用热梗的表达方式或产生笑点的原理，改写成符合人物身份的台词，确认后再锁定；成片 H3 只照录已锁定台词，导演阶段不再另贴库内原句。
- “我超威/我Chovy”是直播喊话的空耳二创，**并非选手 Chovy 本人语录**；原片发布时间和最早空耳创作时间不等于媒体记录时间。已收录词条注明禁用和原创改写建议。
- DeepSeek“蓝色大肥鱼/鲸鱼娘”为社区非官方二创，不应把别人的具体图形设计当成免费商用素材。“嘉豪文学”须避免污名化真实同名者。
- 旧电影、2021 网帖、以前的表情在 2026 年再次传播，只能记为**2026 再传播**，不能标为该年首次创造；不得搬运未授权完整录音、视频、歌词和真人声线。

## H3 同期角色声音提示词模板

- **由 H3 视频生成工作流同时生成声音**，不额外接入独立 TTS 或声音克隆模型。使用已有视频节点，开启 `generateAudio=true`。
- 统一调用 `searchVideoPromptTemplates` 的 `searchCreative(library:"voices")` 检索：音色 `timbre`、情绪 `emotion`、性格 `personality`、语速 `pace`、年龄感 `age`、外国人说中文感 `foreignAccent`、普通话地方口音 `dialect` 和发声方式 `delivery`。优先少量相关模板，避免为一位角色堆叠长串矛盾的形容词。
- `draftVideoPrompt.voiceCast` 按本镜真实说话人填写 `speakerId`、`characterName` 和已确认的声线。按发声方式选择可选的 `sourceId`：画内说话用 `vs01`；旁白用 `vs02`，角色内心独白用 `vs03`，无实体的网文系统用 `vs04` 至 `vs07`。这几类都在说话人编号后写 `says in an off-screen voiceover`，并在该段 `</d>` 后立即说明对应画面人物嘴唇保持闭合；无人入画时写明空镜。音色、情绪和语速按本场另行选择。本次视频按实际首次发声顺序从 `S1` 连续编号，内部切镜不重置。
- 有对白且启用音轨时按场戏需要选择语速。可用自然措辞描述，也可明确写 `speaks at about 1.0 times their usual conversational pace`、`speaks at about 1.1 times their usual conversational pace` 等倍数。数值仅为写法示例，不设统一默认值。角色需要指定语速时可传 `paceId` 或 `speedMultiplier`（二选一）；未指定时不自动补入倍数。实际语速与台词完整性在成片核对。
- “外国人说中文感”和“带地方口音的普通话”只描述**原中文台词的发音习惯**，不能改写台词、编造发音错别字或冒称精确复现方言。两类口音不能同时应用于一个说话人。方言原文要由剧本提供，不能擅自把普通话改成方言。
- `<Audio N>` 仅引用实际绑定的音频文件；声音模板绝不伪造音频引用。静默镜头不强制速度，未讲话角色保持闭嘴。生成视频后，通过成片质检实际听辨 H3 的发声效果；无法确认时标记为未验证。
