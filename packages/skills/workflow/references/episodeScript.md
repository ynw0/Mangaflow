# 逐集剧本

原创和重写剧情先在这里写场次正文，完成剧情复核与必要的对白精修后交 [story-planner.md](story-planner.md) 拆镜。如何在画布上保存和组织剧本，见 [canvas-use.md](canvas-use.md)。

不依赖已断链的旧 knowledge（如 scriptCraft / narrativeGenres）；题材对应的剧情节奏与表演方法写进本集「创作决策」文本节点，或沿用用户已确认的改编策略。

## 输入

- 已确认的项目配置、故事骨架、分集意图与 [adaptationStrategy.md](adaptationStrategy.md)
- 当前集对应原文与事件。只有确实影响本次改动的承接才读取上一集已确认剧本和结尾角色状态
- 需要制作的集数及当前采用的正文。修改时只使用本轮意见和仍然有效的约束
- 用户本轮明确否定的台词、句式或场次，以及前后相关的对话。代写或委派时标明它们是待改处，保留仍然有效的人物关系和剧情事实

## 从零重做的输入

明确列出本次允许进入新稿的输入。可保留的世界规则、人物身份、长期目标从设定中逐项提取。文档中关于某集怎么开场、谁在第几镜做什么、具体台词或预定反转，只有用户明确保留才带入。不得把历史对话中的已作废决定继续当作约束。用户指定小说或要求沿用原文时，先读取本次对应段落，不能仅凭目录或旧大纲推断原文。只要求原创且未指定小说时，按本次创意起稿。

按[工作流入口](../SKILL.md)选择返修范围和编剧会话。只交付前三镜时，先写完整覆盖这三镜的场戏，再取前三镜交付。

## 执行方法

1. 回读输入和当前进度，定位尚需编写或修改的指定集；每次聚焦一集。
2. 明确本集的原文来源、在整部作品中的作用、主要场景内容、删减的情节及结尾位置。最后一集按已确认的结局收束，不强行设置下一集的悬念。
3. 衔接上一集的时间、地点、角色关系、外观和关键道具状态；不把所有已完成剧本重新生成。
4. 组织具体场景，让动作、对白和场景变化推动剧情。用行为呈现心理变化，确有需要时保留独白或旁白。初稿和返修共用[正剧场次怎么展开](shortDramaCraft.md#正剧场次怎么展开)与[对白与人设](shortDramaCraft.md#对白与人设)。把大纲中的关键转变写成完整场戏，让观众跟得上人物怎么听懂、作出选择、承担后果。场次和发声来源按 [场次写法](shortDramaCraft.md#场次) 记录。
5. 写明场号、地点、时间/内外景、本场人物、动作与表情、台词、必要声音和转场。
6. 根据目标时长估算：对白的时间可参考语速，动作和停顿另行计入，不能把字数换算的结果当作实测时长。时长遵循 `production_profile` 和用户约定。
7. 检查本集新信息、冲突变化及结尾期待；镜头技术设计留给 [directorPlan.md](directorPlan.md) 与成片阶段。
8. 修改以实际读取的当前正文为准，保留范围外的事实、台词和场次。写入接口支持修订号时，沿用读取正文时取得的编号。底稿有变化时，先读最新正文，再应用本轮改动。
9. 以人物行动为主的场戏，应让观众看出人物面对的情况如何变化，但不必把每场戏机械分成“目标—阻碍—选择—结果”四拍；日常、过渡和留白场可以通过关系、时间、信息或情绪变化成立，不强造阻碍。保留有助于理解人物和剧情的沉默与日常交流。

## 写入剧本画布

默认在剧本画布维护；每集一个清晰可定位的正式剧本节点。

- 节点标题建议为「第001集剧本｜集标题」；同一集已有节点时原位修改，不得把「修订版」「定稿」当成新的一集。
- 已确认的剧本节点作为该集制作来源；在分集画布上记录剧本的实际来源和位置，不另建一套剧本库。
- 同画布「第001集创作决策」文本节点保存本集的情绪和信息变化、伏笔如何得到回应、人物关系亲疏的变化、关键声音及估算时长的依据；不把分析和模型参数夹进剧本正文。
- 正式剧本将上述创作决定落实为动作、对白、沉默、必要声音和转场。

剧本正文最少包含：

```text
作品名 EP001：集标题
目标时长 / 画幅 / 风格
剧情梗概：本集主要冲突、关键转折和情感变化
1-1 场景名 日/内
人物：本场实际出场人物
△具体环境、动作、表情及必要道具
人物名：台词
需要时标明声源及谁能听见，另标实际播出的旁白和内心独白
转场与下一场；本集结束点
```

## 剧本复核

新写或改过场戏，在拆镜前先用观众第一次听到的顺序读一遍连续对白，再连同动作复核。听清谁在跟谁说话、为什么现在说，对方接住了哪一句，以及观众是否听得懂推动下一步行动的事实。若关键信息已由画面交代，人物可以按自己的目的确认、质疑或继续手上的事。发现接话断了、叫法生硬、角色在复述双方早已知道的背景，按[对白与人设](shortDramaCraft.md#对白与人设)局部修订。同时按系统「中文表达质量与语义保真」检查：是否出现临时简称或生造的缩略语，是否让所有人物都用同一种刻意追求金句的口吻，是否把自然的说法压缩成生硬的短句；对白是否像该人物在该处境说话。复核后仍要保留有意义的语气、行话、沉默和日常交流。用户明确要求独立审稿时，把本轮有效资料与当前稿件交给另一位审核者。

发现会妨碍理解的断点时，指出具体台词或动作，局部修订后只回看受影响的部分。例如收购方把合同递给工程师，若上下文已让观众看懂他想请工程师转交厂长，就可以拆镜。若特意隐去递合同的用意，只需让工程师当下的反应符合他已知的情况，答案可以留到后面。

## 对白精修（使用现有子 Agent，不新增审稿链）

新写或大幅重写的**有对白场戏**，在上面的剧情复核完成后、正式锁定剧本并拆镜前，主 Agent 通过现有 `subAgent` 委派**一次**专业对白精修任务，`tasks[].role: "story"`，沿用编剧 Agent 的模型与思考等级。委派前用 `skillOperator` 的 `list` 确认 `dialoguePolish` 可用；由子 Agent 在任务开始时按 `list → read` 读取该 Skill 的 `SKILL.md`，主 Agent 不重复读取全文。交给它完整相关场戏、必要的前后文、人物关系和已锁定的剧情事实，不用旧剧本碎片替代当前稿。

子 Agent 只报告存在明显问题的**局部连续对话及必要动作**，并与原稿逐处对照；没有值得改的地方可直接报告保留原稿。主编剧只采纳符合人物动机、现场反应和接话逻辑的改写，再按原有复核方式检查人物所知、关键台词、剧情事实、时长、前后场承接。**改后没有明显改善就保留原稿**，不得为了完成步骤而强行润色。对白精修不能替代剧情审稿，也不增加独立审核 Agent 或循环次数。

没有对白、仅做无关道具/镜头/生成参数修改、已有定稿仅需拆镜时不启动该步骤；用户明确要求润色已定稿对白时，按本次授权返回剧本修改并重新处理受影响的分镜。技能被关闭或不可用时按本节既有对白复核自行检查，不虚报独立精修已完成。

## 确认与交接

- 当前集与已确认大纲和策略一致；无擅自增加、漏掉或重写其他集。
- 场号、人物、时间地点明确，动作可表现。保留已确认的原话、事件和结局。
- 写回后核对用户点名否定的旧说法、最新改稿及前后接话。仍有旧句混进来时，先在正式剧本修订受影响的片段，按当前关卡完成确认后再交给分镜。
- 连续对白拆开后仍按原次序接得上。跨场回扣核对观众先前已经获得的线索。
- 写入后回读本次写入的场次或改动片段。普通或半自动模式展示场戏后按关卡等待确认。目标模式在已授权范围内完成剧本复核后继续推进。
- 不把完成通知、用户沉默或内部自检通过当作确认。
- 确认后可进入资产规划 / [directorPlan.md](directorPlan.md)；需要镜头合同时走 [story-planner.md](story-planner.md)。
