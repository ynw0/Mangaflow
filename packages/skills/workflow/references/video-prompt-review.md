# 镜头文生视频提示词工 video-prompt-review

## 职责
根据本次准备结果，审核导演稿是否符合镜头合同、实际素材及制作规则。独立审核时只提交审核结论。H3 格式以 `h3-prompt-writing` 中对应模式的参考为准。

## 输入
- `shotId`、`reviewRequirements`、实际工作流时长与参考槽位、语音策略和可用的相邻镜头信息。内置审核收到的剧情、连续性和硬要求集中在 `reviewRequirements`。
- `draft` 中的 `cinematicPlan`、英文 `prompt` 和简体中文 `promptZh`。外部 MCP 从 `videoPrompt` 的准备结果取得这些审核依据中的合同、工作流和验收项，再审核当前导演稿。

## 格式检查
外部 Agent 跨 Skill 阅读时，先用 `skillOperator` 的 `list` 查明目标 Skill 和 `scope`，再用 `read` 传目标 `name`、`scope` 和目标 Skill 内的 `path`。例如 H3 全参考格式用 `name: "h3-prompt-writing"`、`path: "references/ref-en.txt"`。
- 使用 Ref2VA 时，对照 [ref-en.txt](../../h3-prompt-writing/references/ref-en.txt) 检查六段顺序、字段名、标签语义、关系词、时长记号、运镜与对白标记。
- 纯文生视频或首尾帧模式，对照 [base-en.txt](../../h3-prompt-writing/references/base-en.txt)。
- 不在本文件重复官方百科；格式与官方冲突时以官方为准，单镜/多镜结构按用户合同和实际工作流要求审核。

## 决策规则

先核对已确认的镜头合同和实际参考素材，再核对时长、参考槽位、H3 格式及制作规则，最后审核导演创作质量。

### 语言与结构
- 当前模式要求的各段标题与叙述均为英文，另附简体中文 `promptZh`。`<d>` 内对白、歌词与画面可见文字保留原文。语言标签写语言的英文全称。
- 逐段按定稿核对对白及标点。音频转写的标点整理规则只用于未锁定的内容。
- 连读英文提示词和中文对照。拼写、错别字、病句、用词或生硬译法影响理解时，指出原句和受影响的动作、声源或时序。定稿台词疑似有误时，由编剧核对原稿；审核按确认后的原话验收。
- 提示词与时间轴须符合准备结果中的 `workflow.duration`。Ref2VA 用 `detailed_description`，纯文本和首尾帧用 `integrated_multimodal_description`。首镜标 `[Shot 1]`，Ref2VA 可在它之前说明全局风格。允许切镜时后续 `[Shot N] At MM:SS.mmm` 按时序展开。用户明确要求单镜时只用一个 `[Shot 1]`。对白计划在 `cinematicPlan.dialogue` 逐句核对。
- `summary` 的任务类型按实际模式与 [video-director.md](video-director.md) 确定，Ref2VA 默认 `[reference generation]`。

### 镜头结构与槽位
- 按实际引用方式核对素材。Subject 定义及 retention_analysis 属于 Ref2VA。首尾帧按 base-en.txt 核对开场和实际最后一镜的帧对齐。
- 按用户批准的镜头合同审核：明确单镜到底时，正文出现内部切镜、反打或蒙太奇才应退回；允许剪辑时，反打、跨场景、闪回、蒙太奇、时间跳跃均可，按 [Shot N] 和递增切点核对时长、场面与对白连续性，不因剪辑形式本身退回。
- 新多镜稿须提供 `cinematicPlan.shots`：逐镜核对 id、起止时间、实际构图/机位、动作和必要的 `continuityIn/continuityOut`。镜头连续覆盖全片，绝不能用旧的全局 `camera` 代替逐镜规划。单镜及历史审核记录可省略该数组。全局 `beats/dialogue` 为全片绝对时间，不在切镜处重新从零计时。
- 提示词中的参考标签与用途须和 `workflow.references` 的实际槽位逐项对应。Picture 只能引用本镜已批准的槽位；动作句使用本镜登记名，主体标签须与本镜身份定义一致。
- Subject 按身份定义，Picture 按实际槽位编号。同一主体的多个参考状态引用同一个 Subject，逐张说明用途。每个身份或状态槽都要被对应主体引用。`retention_analysis` 覆盖已定义 Subject。独立 Picture 条目用于实际成立的帧或构图锚，关系词与其用途及保留范围一致。普通参考图的用途可以描述为变形状态，不能假定模型会在指定帧复现。
- 挂接的视频与音频参考在 `retention_analysis` 使用实际的 `<Video N>`、`<Audio N>` 标签，每行填写一个符合该素材类型和用途的官方关系词。无对应文件却引用标签，判不合格。

### 剧情、外形与连续性
- 按 `reviewRequirements` 核对动作、因果、对白、人物持物与入出镜。遗漏硬性事实、另写一场戏、把动作改成产品说明或放宽编剧要求，判不合格。
- 场次或空间第一镜的开场站位与 `continuity_in` 一致。按[已确认的分镜](story-planner.md)核对观众在第一拍能看到或听到什么。镜尾按 `continuity_out` 核对状态承接，画外人物和物件仍保持原来的位置及关系。合同明确要求镜尾可见或可听时，核对机位和声画能否交付该事实。其余留在画外的状态无需进入镜尾构图。
- 外形以该槽的 `approved_image_prompt` 为准，剔除原画棚拍和画幅设定。`allowed_variant_changes` 属于允许的变体，当前外形取自批准资产。跨镜锁面事实须写入对应 `<Subject N>` 定义并在 `retention_analysis` 标明保留关系。沿用冲突旧外形或把整段原画贴进动作句，判不合格。

### H3 角色声音模板审核
- 有对白且开启同期音轨时，核对 `voiceCast` 已指定的语速，其余采用 `speechPolicy` 的默认语速。停顿、重音与口气按角色此刻的表演安排，台词完整性在成片验收。
- 先对照定稿核对每段是谁在画内或画外发声、谁听得见，再对照 `voiceCast` 核对 `(Sx)`、声线与指定语速。若画内对白被配置为旁白，把冲突定位到声源配置并退回调用方。声线、口音和情绪保留原台词，音频引用取自实际素材。
- 身体局部入画时，Subject 仍为实际人物。只露出手或脚的现场说话人仍可能被同场人物听见。核对位置和听觉关系，按定稿区分现场对白和观众专属旁白。
- 字数估时只提示风险，估算差值本身不退稿。实际对白是否完整、听感和口型同步在成片核对。

### 声画与方向性道具
- `overall_soundscape` 只保留全片一直在的环境层。瞬间声、对白或警报写进该段，或 `partially_copy` 声音在指定开始时刻前出现，判不合格。完整台词放在对应的 `<d>` 标签内，声音两段避免复写。文件时间与成片不一致却用 `fully_copy`，判不合格。
- 按正文核对停顿、先后动作和收句。核实发声时段处在片段内，镜尾反应和台词中断按定稿处理。口型与实际发声对应。见 `video-director.md`「说话时序」。
- 核对 `dialogueTiming` 时逐句对照正文。分镜确实要求先做完再开口时，单列前置节拍并用 `afterBeat` 指定；同一时刻能做的动作按原场戏并行。直接接话可以只写说话人和原话。画内口型按实际发声核对，齐声共用一个 `<d>`。对白刚好能放下时，说明起声偏移风险。
- 两段不同台词交叠时，对照定稿核对是否确有抢话及哪一句须听清。有交叠依据时保留各自的原话和声源。定稿要求分开说、未交代抢话或交叠会遮住关键台词时，指出冲突并退回。多人齐声说同一句话使用合并的说话人编号。
- 跨镜接话或跨场回扣时，用 `adjacentShots` 核对观众先前能听到或看见的依据。相邻问答保留完整顺序，较早交代的线索可以直接回扣。依据不足时指出待核的回话或决定，请调用方回读相关场次。原分镜确实漏掉关键台词或事件时退回分镜。
- 按剧本核对动作和声音的因果。突然绊倒时，对方不应停下来等接触；犹豫、蓄力或改变决定所需的准备动作应当保留。若决定由画外声音触发，核对人物在什么时刻听见什么；只有观众听见的旁白不能驱动角色反应。跨镜从上镜实际末态接起。
- 方向性道具或特效的初始朝向要明确。动作换向、转动或接触时，核对其影响的前缘、连接点和落点。稳定朝向沿用前文。仅在遗漏或矛盾影响动作及承接时退稿。见 `video-director.md`。

### 其它正面检查
- Ref2VA 定义句须能定位参考来源、识别主体及其用途。因外形遗漏退回时，点明哪项已批准特征缺失，以及它会怎样影响身份辨认、跨镜连续性或本镜动作的理解。场景只写空词、动作或对白写进定义段、`summary` 复述素材清单或改错任务类型，仍须修订。
- 开头交代观众辨认主体、空间和动作需要的信息。后续核对发生的变化，以及对承接有影响的事实。上一段持续不变的光线、机位、位置和环境底声可沿用。瞬间事件标清发生时刻与主体。有配乐时核对它与当前场戏的关系，无配乐时 `non_diegetic_music` 填 `N/A`。
- 按实际构图和声场核对排除要求。发现正面叙述引入了合同排除的对象、漏掉应听见的声音或把画外动作写成可见画面时，定位到具体句段。通则见 [common.md](common.md#成片正面改写通用)。

### 模式真实性与动作负荷审核

- 按 MiniMax 官方 Ref2VA 指南允许 [keyframe completion] 以及描述 <Picture N> 作为镜头第一帧、关键帧或构图锚的语义；不可仅因这些用语拒稿。仅在没有专用 refs.first_frame / refs.last_frame 绑定时，拒绝逐像素完全一致、确定性强锁帧等超出输入能力的承诺。需要首尾帧驱动的请求应核查实际工作流、参考槽位和生成任务模式。

- 大型机械变形核对零件来源、连接方式、变动前后状态及必要时间。如果五秒内多个机械阶段无法同镜看清，应退回上游拆镜或资产确认，而非要求导演追加更长时间清单。

- QC 的 unverified 不等于通过；同一 requirementId 的 pass/fail 相互冲突必须复看实片，不能按重复数量计分。

### 信息密度与自适应长度审查
- 按播放顺序读最终正文，核对观众能否辨认本镜实际要交代的人、事、起因和结果。新造缩写、生硬简语或只有下游才知道的代号若遮住了这些信息，指出具体句子。定稿保留的人物口吻和后续才揭晓的信息照常处理。篇幅按理解这些声画需要多少内容判断。
- 同一环境、镜头方式、灯光、人物身份、背景声被逐段复述，或大段只有“电影级、史诗感、极致细节”等无可观察信息时，提出**定位明确的一次删减建议**；仅当其导致动作模糊、冲突或严重稀释主要事件时退回。
- 没有必要时不要求补特效、复杂光影、过度心理描写或额外动作；写清起点、动作路径、结果、主体与参考绑定即可。
- 不能为了短而删去剧本硬要求、身份锁、重要运动接触点、对白/口型、Ref2VA 标签与保留关系；审核要以正确性为先。
- 审核意见优先只指出实质缺漏或矛盾，不反复要求全篇重写、长篇扩写；同一问题合并 findings，避免无效多轮重写。

### 导演创作质量
- 顶视稍斜俯时核对俯视关系和空间方向；角色外形使用具体辨识特征并沿用已批准设定。
- 机械变形核对起始、中间和末态的零件对应、连接点和运动顺序。关键零件凭空出现、接触后无可见结果，或给定画幅与时长内读不清剧情硬要求时，定位到对应部件和时间段退回。
- 缺少必需的视觉信息（例如打斗无接触点、施法无来源/方向、人物反应无观察对象）或视觉设计与镜头目的冲突时，给出明确 findings 退回。
- 剧情靠读数或动作让观众理解结论时，按定稿核对比较依据，以及这个发现对人物决定和后续结果的影响。若镜头省略了定稿已经交代的依据，指出遗漏处。剧本本身尚未交代时，指出待确认的因果关系，交回上游。
- 固定镜头、少量表情和没有特效的镜头，只要能准确表达当前剧情，应当合格；**不因为镜头不运动、没有特效或词数短而扣分**。
- 同一内部镜头若同时要求不相容的运镜、全景与极特写动作、短时间堆叠多个高潮，或镜头之间缺少必要的状态承接、光源方向自相矛盾，判不合格。
- 审核不代写导演方案；将发现的问题定位到对应动作/时间段并提出修改目的，由原导演重写。身份锁、Picture、对白、格式等硬检查仍按原规则执行。

## 提交与交接

通过审核时，提交 `status: "ok"`、`coverage` 和 `findings: []`。合同指定了收尾构图或可见事实时，可用 `framingEvidence` 记录对应证据。`coverage` 按 `reviewRequirements` 的原编号逐项填写 `{ requirementId, evidence }`。证据定位到稿件中的事实或时间点。画外承接说明与画内安排是否冲突，禁止项写明核对范围。

稿件有明确缺陷时，提交 `status: "rejected"` 和非空 `findings` 数组。每条含 `requirementId`、`location`、`evidence` 和 `fixTarget`。退回时省略 `coverage` 与 `framingEvidence`，由导演根据问题定向返修。缺少核验某项所必需的稿件内容时，在对应要求下说明具体缺项。若无法完成审核，向调用方说明缺少的输入，审核保持未通过。

核验接话或回扣所需的分镜或场次依据缺失时，在退回结果中另填 `needsAdjacentShots: true`，并指出需回读的场次或镜头。调用方补齐合同后重新派发。依据齐全时按实际稿件缺陷定向返修。

- 内置独立审核用 `submitResult({ result: { ... } })` 提交上述判决。`result` 只使用 `ok` 或 `rejected` 分支对应的字段。上游的 `shotId` 用于核对合同，审核结果无镜号字段。审核员提交后由服务端处理。已有节点请求 `node.write: true` 时，成功结果中的 `written: true` 表示英文稿、中文对照和 `reviewId` 已写入目标视频节点。
- 外部 MCP 在 `videoPrompt` 的 `args.action: "submit"` 中同时传 `preparationId`、`draft` 和 `review`。上述判决字段直接放在 `review` 对象内。服务端返回 `reviewId`、`generationRequest` 和 `written: false`。已有节点需要写回时，调用 `node:setPrompt`，使用 `generationRequest.prompt`、原稿的 `promptZh`、`reviewId` 和服务端返回的 `expectedRevision`。写回后回读视频节点。
- 生成前按当前运行模式及已获授权范围推进。提示词审核通过记录使用 `reviewId`，成片质检结论另查生成任务的实际结果。
