# 视频提示词复核与可选独立审核

## 职责
先读取画布实际正文，对照已确认的镜头合同、实际素材和模型规范复核。主 Agent 可直接原位修改问题；未发现实质问题时保留原稿。只有明确选择独立审核时才按文末结构提交审核结论。提示词的具体写法见 [video-director.md](video-director.md)；本文件是验收与退回标准。H3 格式以 `h3-prompt-writing` 中对应模式的参考为准。

## 输入
- `shotId`、`reviewRequirements`、实际工作流时长与参考槽位、语音策略和可用的相邻镜头信息。内置审核收到的剧情、连续性和硬要求集中在 `reviewRequirements`。
- `draft` 中的 `cinematicPlan`、英文 `prompt` 和简体中文 `promptZh`。外部 MCP 从 `videoPrompt` 的准备结果取得这些审核依据中的合同、工作流和验收项，再审核当前导演稿。

## 格式检查
外部 Agent 跨 Skill 阅读时，先用 `skillOperator` 的 `list` 查明目标 Skill 和 `scope`，再用 `read` 传目标 `name`、`scope` 和目标 Skill 内的 `path`。例如 H3 全参考格式用 `name: "h3-prompt-writing"`、`path: "references/ref-en.txt"`。
- 使用 Ref2VA 时，对照 [ref-en.txt](../../h3-prompt-writing/references/ref-en.txt) 检查六段顺序、字段名、标签语义、关系词、时长记号、运镜与对白标记。
- 纯文生视频或首尾帧模式，对照 [base-en.txt](../../h3-prompt-writing/references/base-en.txt)。
- 不在本文件重复官方百科；格式与官方冲突时以官方为准，单镜/多镜结构按用户合同和实际工作流要求审核。

## 决策规则

先核对已确认的镜头合同和实际参考素材，再核对时长、参考槽位、H3 格式及制作规则，最后核对剧情可读性、表演和语言。初审和复审均完成所有适用项后再提交，即使前面已发现足以退稿的问题。把本轮确认的实质问题一次列齐，同一原因合并。

### 语言与结构
- 当前模式要求的各段标题与叙述均为英文，另附简体中文 `promptZh`。英文正文的 `<d>` 块采用 `<d>[Language] …</d>`，以方括号内的英文语言全称开头，随后照录对白或歌词及其标点。画面可见文字保留原文。
- 逐段按定稿核对对白及标点。音频转写的标点整理规则只用于未锁定的内容。
- 在 `bilingualConsistency` 核对中英文事实一致后，再单独通读 `promptZh`。逐句看物件、动作和声线说明是否通顺。即使意思能猜出来，直接照搬资料中生硬的词组、搭配不当或省略改变了原意，都应引用原句退回局部修订。台词、画面上实际显示的文字、专有名称和规定的标记应照录，定稿台词疑似有误时由编剧核对。
- 提示词与时间轴须符合准备结果中的 `workflow.duration`。Ref2VA 用 `detailed_description`，纯文本和首尾帧用 `integrated_multimodal_description`。首镜标 `[Shot 1]`，Ref2VA 可在它之前说明全局风格。允许切镜时后续 `[Shot N] At MM:SS.mmm` 按时序展开。用户明确要求单镜时只用一个 `[Shot 1]`。对白计划在 `cinematicPlan.dialogue` 逐句核对。
- `summary` 的任务类型按实际模式与 [video-director.md](video-director.md) 确定，Ref2VA 默认 `[reference generation]`。

### 镜头结构与槽位
- 按实际引用方式核对素材。Subject 定义及 retention_analysis 属于 Ref2VA。首尾帧按 base-en.txt 核对开场和实际最后一镜的帧对齐。
- 按用户批准的镜头合同审核：明确单镜到底时，正文出现内部切镜、反打或蒙太奇才应退回；允许剪辑时，反打、跨场景、闪回、蒙太奇、时间跳跃均可，按 [Shot N] 和递增切点核对时长、场面与对白连续性，不因剪辑形式本身退回。
- 存在 `cinematicPlan.shots` 时检查其一致性；直接编写正文无须补造规划。逐镜核对编号、起止时间、实际构图、动作和必要的连续性，镜头时间应覆盖全片。单镜的空 `shots` 数组与省略同样有效。历史审核记录可省略该数组。全局 `beats` 和 `dialogue` 使用整段视频的绝对秒数。
- 提示词中的参考标签与用途须和 `workflow.references` 的实际槽位逐项对应。Picture 只能引用本镜已批准的槽位；动作句使用本镜登记名，主体标签须与本镜身份定义一致。
- Subject 按身份定义，Picture 按实际槽位编号。同一主体的多个参考状态引用同一个 Subject，逐张说明用途。每个身份或状态槽都要被对应主体引用。`retention_analysis` 覆盖已定义 Subject。独立 Picture 条目用于实际成立的帧或构图锚，关系词与其用途及保留范围一致。普通参考图的用途可以描述为变形状态，不能假定模型会在指定帧复现。
- 挂接的视频与音频参考在 `retention_analysis` 使用实际的 `<Video N>`、`<Audio N>` 标签，每行填写一个符合该素材类型和用途的官方关系词。无对应文件却引用标签，判不合格。

### 剧情、外形与连续性
- 按 `reviewRequirements` 核对动作、因果、对白、人物手中拿着的物件，以及进入或离开画面的动作。遗漏硬性事实、另写一场戏、把动作改成产品说明或放宽编剧要求，判不合格。
- 按[已确认的分镜](story-planner.md)核对开场如何承接 `continuityIn`。已经完成的动作在开场应呈现结果，有明确回放安排时按定稿拍。在镜头结束时，按 `continuityOut` 核对下一镜需要延续的状态，画外人物和物件保持实际位置及关系。合同指定镜尾可见或可听的事实时，核对机位及声音安排能否呈现这些事实。
- 外形以该槽的 `approved_image_prompt` 为准，剔除原画棚拍和画幅设定。`allowed_variant_changes` 属于允许的变体，当前外形取自批准资产。不同镜头间必须保持一致的可见特征须写入对应 `<Subject N>` 定义并在 `retention_analysis` 标明保留关系。沿用冲突旧外形或把整段原画贴进动作句，判不合格。

### H3 角色声音模板审核
- 有对白时，核对用户已指定的语速、声线及表演要求。未指定语速无需补写默认倍数或全局说明。停顿、重音及口气按当下场戏安排，完整性在成片中听辨。
- 逐段核对画外音的固定短语，以及 </d> 后关于人物嘴唇保持闭合的说明是否对应当时画面中的人物。画面无人时核对空镜说明。先对照定稿核对每段是谁在画内或画外发声、谁听得见，再对照 `voiceCast` 核对 `(Sx)`、声线与指定语速。确认编号与本次视频实际说话人一一对应，未发声的人物没有被标为说话人；不同视频不强制沿用 S 编号。若画内对白被配置为旁白，把冲突定位到声源配置并退回调用方。声线、口音和情绪保留原台词，音频引用取自实际素材。
- 身体局部入画时，Subject 仍为实际人物。只露出手或脚的现场说话人仍可能被同场人物听见。核对位置和听觉关系，按定稿区分现场对白和只有观众才能听到的旁白。
- 根据字数估算的时长只用于提示风险，不能仅凭估算结果与计划时长的差异退回稿件。实际对白是否完整、听感和口型同步在成片核对。

### 声画与方向性道具
- `overall_soundscape` 只描述整段视频中持续存在的环境声。瞬间声、对白或警报写进该段，或 `partially_copy` 声音在指定开始时刻前出现，判不合格。完整台词放在对应的 `<d>` 标签内，不要在两个声音描述段落中重复整段台词。文件时间与成片不一致却用 `fully_copy`，判不合格。
- 核对 `dialogueTiming` 时根据对白计划定位开口、说完及停顿的时间，检查正文中的接话顺序、动作和实际声源。正文写了具体对白秒数时，与计划逐句对照。动作节拍记录动作本身，可以和发声同时发生，确有依赖时再核对 `afterBeat`。镜尾反应与台词中断按定稿处理。见 `video-director.md`「说话时序」。
- 两段不同台词交叠时，对照定稿核对是否确有抢话及哪一句须听清。有交叠依据时保留各自的原话和声源。定稿要求分开说、未交代抢话或交叠会遮住关键台词时，指出冲突并退回。多人齐声说同一句话使用合并的说话人编号。
- 跨镜接话或跨场回扣时，用 `adjacentShots` 核对观众先前能听到或看见的依据。相邻问答保留完整顺序，较早交代的线索可以直接回扣。依据不足时，指出需要进一步核实的回应或决定，请调用方重新读取相关场次的内容。原分镜确实漏掉关键台词或事件时退回分镜。
- 按剧本核对动作和声音的因果。突然绊倒时，对方不应停下来等接触；犹豫、蓄力或改变决定所需的准备动作应当保留。若决定由画外声音触发，核对人物在什么时刻听见什么；只有观众听见的旁白不能驱动角色反应。跨镜头的动作和状态，应从上一镜实际结束时的情况接起。
- 方向性道具或特效的初始朝向要明确。动作换向、转动或接触时，核对其影响的前缘、连接点和落点。稳定朝向沿用前文。仅在遗漏或矛盾影响动作及承接时退稿。见 `video-director.md`。

### 其它正面检查
- Ref2VA 定义句须能定位参考来源、识别主体及其用途。因外形遗漏退回时，点明哪项已批准特征缺失，以及它会怎样影响身份辨认、跨镜连续性或本镜动作的理解。场景只写空词、动作或对白写进定义段、`summary` 复述素材清单或改错任务类型，仍须修订。
- 开头交代观众辨认主体、空间和动作需要的信息。后续核对发生的变化，以及对承接有影响的事实。上一段持续不变的光线、机位、位置和环境底声可沿用。瞬间事件标清发生时刻与主体。有配乐时核对它与当前场戏的关系，无配乐时 `non_diegetic_music` 填 `N/A`。
- 按实际构图和声场核对排除要求。发现正面叙述引入了合同排除的对象、漏掉应听见的声音或把画外动作写成可见画面时，定位到具体句段。通则见 [common.md](common.md#成片正面改写通用)。

### 模式真实性与动作负荷审核

- 按 MiniMax 官方 Ref2VA 指南允许 [keyframe completion] 以及描述 <Picture N> 作为镜头第一帧、关键帧或构图锚的语义；不可仅因这些用语拒稿。仅在没有专用 refs.first_frame / refs.last_frame 绑定时，拒绝逐像素完全一致、确定性强锁帧等超出输入能力的承诺。需要首尾帧驱动的请求应核查实际工作流、参考槽位和生成任务模式。

- 大型机械变形核对零件来源、连接方式、变动前后状态及必要时间。如果五秒内多个机械阶段无法同镜看清，应退回上游拆镜或资产确认，而非要求导演追加更长时间清单。

- QC 的 unverified 不等于通过；同一 requirementId 的 pass/fail 相互冲突必须重新查看实际生成的视频，不能按重复数量计分。

### 信息密度与自适应长度审查
- 按播放顺序读最终正文，核对观众能否辨认人、事、起因和结果。有人物或物件的日常叫法时，指出新稿中生硬的临时简称和不通顺的省略，即使能从上下文猜出意思。定稿保留的人物口吻和后续才揭晓的信息照常处理。篇幅按理解声画所需的信息判断。
- 按播放顺序判断观众能否看清关键变化、听懂人物的回应。持续状态可能是观众判断变化的依据。需要退回时，指出具体哪处造成误解、违背定稿或无法拍清，以及它影响了哪一段剧情。
- 没有必要时不要求补特效、复杂光影或额外动作。写清起点、动作路径、结果、主体与参考绑定即可。
- 不能为了缩短篇幅而删去剧本硬性要求、必须保持一致的身份特征、重要动作的接触点、对白及口型要求、Ref2VA 标签和保留关系；审核要以正确性为先。
- 将已确认的问题定位到句段或时刻，提出局部修订目标。

### 导演创作质量
- 顶视稍斜俯时核对俯视关系和空间方向；角色外形使用具体辨识特征并沿用已批准设定。
- 机械变形核对变形开始、中间过程及结束时的零件对应关系、连接点和运动顺序。关键零件凭空出现、接触后无可见结果，或给定画幅与时长内读不清剧情硬要求时，定位到对应部件和时间段退回。
- 缺少必需的视觉信息（例如打斗无接触点、施法无来源/方向、人物反应无观察对象）或视觉设计与镜头目的冲突时，给出明确 findings 退回。
- 剧情靠读数或动作让观众理解结论时，按定稿核对比较依据，以及这个发现对人物决定和后续结果的影响。若镜头省略了定稿已经交代的依据，指出遗漏处。剧本本身尚未交代时，指出待确认的因果关系，交回上游。
- 固定镜头、少量表情和没有特效的镜头，只要能准确表达当前剧情，应当合格；**不因为镜头不运动、没有特效或词数短而扣分**。
- 运镜停止的时刻在正文和导演计划里一致。镜尾保持描述的是所需构图成立后的时段，机位可以提前停住，让人物完成最后的走位或动作。用已确认的空间关系核对走位能否在时长内完成，缺尺寸时按明确的方向、起点和到达状态判断。
- 同一镜头安排不相容的运镜、景别或动作，或镜头之间缺少必要的状态承接时，指出具体冲突。
- 主 Agent 将问题定位到具体动作、语句或时间段，在现稿中修改必要内容；独立审核仅提供意见，不代写。身份特征一致性、Picture 引用、对白和格式等必须通过的检查仍按原规则执行。

## 提交与交接

普通画布复核不需要以下审核证据格式或审核 ID。读回当前正文、发现问题原位修订即可；只有选择独立审核时才使用以下旧式结构。

通过审核时，提交 `status: "ok"`、`coverage` 和 `findings: []`。合同指定了收尾构图或可见事实时，可用 `framingEvidence` 记录对应证据。`coverage` 按 `reviewRequirements` 的原编号逐项填写 `{ requirementId, evidence }`。证据定位到稿件中的事实或时间点。画外承接说明与画内安排是否冲突，禁止项写明核对范围。

稿件有明确缺陷时，提交 `status: "rejected"` 和非空 `findings` 数组。每条含 `requirementId`、`location`、`evidence` 和 `fixTarget`。退回时省略 `coverage` 与 `framingEvidence`，由导演针对指出的问题进行修改。缺少核验某项所必需的稿件内容时，在对应要求下说明具体缺项。若无法完成审核，向调用方说明缺少的输入，审核保持未通过。

核验接话或回扣所需的分镜或场次依据缺失时，在退回结果中另填 `needsAdjacentShots: true`，并指出需要重新读取的场次或镜头。调用方补齐合同后，重新委派审核任务。依据齐全时，针对稿件中实际存在的问题进行修改。

- 内置 Agent 的独立审核使用 `submitResult({ result: { ... } })` 提交上述审核结论。`result` 只使用 `ok` 或 `rejected` 分支对应的字段。上游的 `shotId` 用于核对合同，审核结果无镜号字段。审核员提交后由服务端处理。已有节点请求 `node.write: true` 时，成功结果中的 `written: true` 表示英文稿、中文对照和 `reviewId` 已写入目标视频节点。
- 外部 MCP 在 `videoPrompt` 的 `args.action: "submit"` 中同时传 `preparationId`、`draft` 和 `review`。上述审核结论字段直接放在 `review` 对象内。服务端返回 `reviewId`、`generationRequest` 和 `written: false`。已有节点需要写回时，调用 `node:setPrompt`，使用 `generationRequest.prompt`、原稿的 `promptZh`、`reviewId` 和服务端返回的 `expectedRevision`。将提示词写入节点后，重新读取视频节点中的内容进行核对。
- 独立审核记录仅供追溯，普通提示词保存和生成不依赖 `reviewId`。成片验收使用当前生成记录中的剧情合同或实际提示词。
